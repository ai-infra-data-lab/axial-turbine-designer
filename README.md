# 軸流タービン設計 翼列モデル版 0.3

ガスタービン用軸流タービンの概念設計を行う独立したローカルWebアプリです。Python標準ライブラリのみで動作し、外部CDNや外部サービスは使いません。既存アプリのコード・データベースは変更しません。

## 起動

Python 3.10以上を用意します。アプリ本体には追加のPythonパッケージは不要です。GitHubから取得する場合は、リポジトリをcloneするか「Code → Download ZIP」でダウンロードし、展開してください。

Windowsで `start.bat` をダブルクリックしてください。既定のブラウザーで http://127.0.0.1:8782 を開きます。起動したコンソールを閉じるとサーバーが終了します。

同梱の `../.runtime/python/python.exe` がある場合はそれを使用し、なければPATHのPythonを使います。手動起動は、このフォルダーで `python server.py`。別ポートは `python server.py --port 8784 --open`。URLは localhost ではなく 127.0.0.1 を使ってください。

## 初回の操作

1. 起動時は「仮の入力例」を表示します。実機の設計条件に置き換え、案件名・メモを設定してください。
2. 必要なら管理アプリからJSONを出力し、「管理アプリのJSONを選択」で読込み、タービン部品を選んで紐付けます。
3. 入口全温・全圧、流量、回転数、要求ガス出力、物性、指定段効率、平均半径、軸流速度を設定します。
4. 段を追加・削除し、仕事配分比と反動度を指定します。
5. 編集する静翼・動翼を選び、断面の角度・厚み・スパン位置・軸方向／周方向移動を指定して「形状を更新」。
6. 「1D計算」で必要流路と速度三角形を確認します。警告も確認し、「保存」でローカルDBに記録します。
7. JSONは設計全体の交換用、OBJは選択翼列の単翼形状の確認用です。

保存先は `data/designs.sqlite3`。上書き時はrevisionを確認し、競合時は書込みを拒否します。保存履歴はDB内に保持しますが、履歴復元画面は初期版にはありません。バックアップは「JSON出力」で行えます。JSON読込は結果を未実行に戻します。同じIDが保存済みの場合は「開く」を使ってください。

翼列モデル版の設計schema・JSON交換bundleはversion 3です。旧版version 1/2は読込時にメモリー上で移行し、保存操作まではDBの原本を変更しません。入力ハッシュが変わる旧計算結果は未実行に戻します。新版の交換JSONは、新しい計算方式を解釈できない0.1/0.2版では読み込めません。

## 翼面とスパン方向

基本の角度・厚み指定に加え、分布曲線方式と両面直接方式に対応します。詳しい操作は `CURVE_EDITING.md` を参照してください。

- 各段に静翼・動翼を持ち、翼列ごとに安定したIDと断面IDを保存します。
- 基本方式は、軸方向コード、入口／出口金属角、取付角を使う3次Hermite中心線に法線方向の厚みを与えます。旧版の保存データはそのまま読み込めます。
- 分布方式では、翼に沿う中心線角度と法線厚みを3～41点で定義します。点の数値編集・ドラッグ・追加削除が可能です。取付角は角度の積分結果です。
- 両面直接方式では、面A・面Bをそれぞれ3次B-splineで定義します。変換時に各面17または25個の制御点を選び、数値・ドラッグで編集します。前縁始点を共有し、前縁接線の連動を選択できます。
- 変換前の定義を断面ごとに最大8件保存し、元形状を重ね合わせて表示します。変換時と編集後の最大差・RMS差を確認できます。直接編集から分布曲線への自動再近似はせず、「変換前へ戻す」を使います。
- 0～100%の幾何学的スパンに2～21個の設計断面を配置します。旧来の基本方式同士はパラメータ補間、曲線編集を含む断面間は各面の正規化弧長を対応させた座標補間です。
- 表示断面は標準17断面に実際の設計スパン位置を追加します。設計断面と表示分割は別です。
- 積み重ねの初期基準は前縁中心。軸方向移動がスイープ、周方向移動がリーンを制御します。円筒配置で3D表示します。直接編集で前縁自体を動かした場合は、その局所座標も形状に含まれます。
- 面A/Bの識別を固定し、翼列ごとにどちらを想定圧力面とするか指定できます。名称は流れ解析による圧力分布の保証ではありません。
- 自己交差・隣接翼交差に加え、曲率、前縁接線差、前後縁の隙間、両面間距離と翼間最小隙間の近似を表示します。厳密な最小肉厚・有効スロート・断面間の3D面交差・製造可否は保証しません。
- OBJはm単位の単翼表面メッシュです。ハブ・チップ端面を閉じておらず、製造用ソリッドではありません。

## 非冷却1Dモデル

左側の「計算方式」で、従来の指定段効率方式と、新しい翼列損失・偏差方式を切り替えます。新方式はSoderberg型（2016掲載式）／指定損失Y、Ainley–Mathieson／Aungier／指定偏差に対応します。翼列ごとの金属角・コード・スロート面積比を明示入力し、流出角・損失・出口全圧・効率・仕事を求めます。入力手順、係数の定義と適用範囲は `AERODYNAMIC_MODELS.md` を参照してください。

新方式では要求出力は比較目標になり、段効率・反動度・仕事配分比は入力拘束として使いません。一定軸流速度と流出角によって仕事を決め、損失を出口圧力・効率へ反映します。背圧から流量を解く固定流路解析ではありません。

以下は従来の指定段効率方式の説明です。


定比熱理想気体、一定平均径、一定軸流速度、段ごとに指定された全全効率を仮定します。冷却・抽気・機械損失はなく、入力の要求出力はガスから取り出す仕事です。ガス定数は `Rgas = cp (gamma-1)/gamma` で導きます。

各段の仕事は、要求出力を流量で割り、仕事配分比で配ります。

```
U = 2π rpm rm / 60
Δh_i = (Power / mass_flow) weight_i / Σweight
Cθ1 = U(1 - reaction) + Δh_i/(2U)
Cθ2 = U(1 - reaction) - Δh_i/(2U)
T0,out = T0,in - Δh_i/cp
p0,out = p0,in [1 - Δh_i/(ηstage cp T0,in)]^(gamma/(gamma-1))
T = T0 - (Cax²+Cθ²)/(2cp)
p = p0 (T/T0)^(gamma/(gamma-1))
A = mass_flow/(rho Cax), height = A/(2πrm)
```

静翼を全温・全圧一定とし、指定効率による段損失を動翼側に集約します。角度は軸方向から正回転方向を正とし、動翼では相対速度、静翼では絶対速度で定義します。全体効率は段効率の単純平均とは異なります。

出力は全全効率、膨張比、トルク、段仕事、流量・負荷係数、速度三角形、入口／出口の絶対・相対Mach数、必要面積・翼高さ、仕事・エネルギー残差です。質量収支は必要面積の逆算による恒等確認であり、独立した流量予測の検証ではありません。

形状側のハブ・チップ半径から求める面積と、性能側の必要面積が5%以上異なると警告します。両者を自動で一致させる最適化は行いません。従来方式では翼面の編集は損失や効率を変更しません。新方式では金属角・コードを明示転記でき、流出角偏差と集約損失を計算します。翼面曲率・厚みからの詳細損失予測や入射損失補正は未実装です。

## 管理情報との紐付け

管理アプリのJSON交換形式を読み、`(project_id, component_id)` と入力元revision、プロジェクトのスナップショット・SHA-256を保存します。部品は種別 `turbine` に限定します。入力項目は自動転記せず、元の単位・定義を確認して数値を設定してください。管理アプリのDBには直接アクセスしません。

参照元の最新状態はライブ監視しません。管理情報を変更した場合は新しいJSONを読み、同じ部品を選択して「紐付け／参照元を更新」を実行します。紐付けの変更を含め、設計入力・形状の変更は画面上の結果を失効させます。

計算結果には入力スナップショット・ハッシュ、モジュール版、単位・座標規約、実行ID・日時・状態を保存します。結果の管理アプリへの反映は将来の明示的取込機能とし、現版ではJSON出力までです。

## 検証

`python -m unittest -v test_app.py test_profiles.py test_aerodynamics.py` で数値・形状・保存・HTTP APIを検証します。開発用DOMテストはNode.js 20以上で `npm install --ignore-scripts`、`npm test` を実行します。ロックファイルどおりの開発環境には `pnpm install --frozen-lockfile --ignore-scripts`、`pnpm test` を使います。Pythonを別途指定する場合は環境変数 `PYTHON` を設定してください。`npm run check` で画面スクリプトの構文を確認できます。アプリ本体にはNodeは不要です。検証結果と未確認事項は `VERIFICATION.md` を参照してください。
